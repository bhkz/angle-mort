# UX — critique croisée des huit concepts

Évaluation de conception après contribution indépendante ; aucune observation de joueurs n'est prétendue.

| Concept | Force UX | Objection principale | Correction concrète | Verdict |
| --- | --- | --- | --- | --- |
| C1 — Port | Robot et destination donnent un geste immédiatement imaginable. | Occlusion 3D et lignes croisées peuvent rendre le téléphone imprécis. | Caméra fixe, six destinations distinctes, sélection par toucher puis destination, focus isolant le circuit. | Retenir. |
| C2 — Pièce témoin | Un lieu familier réduit le besoin de vocabulaire technique. | Comparer deux instants devient une chasse aux pixels. | Cadre identique, objets manipulables suffisamment grands, bascule avant/après plutôt que deux minuscules vues. | Modifier. |
| N1 — Appartement | Aménagement et besoins quotidiens rendent les enjeux concrets. | Dialogues et routines peuvent devenir du travail ménager numérique. | Une seule routine initiale, exécutée instantanément après sa première résolution ; montrer le temps libéré. | Retenir comme finaliste narratif. |
| N2 — Montage | Une contradiction peut être vue au lieu d'être expliquée. | Timeline, recadrage et synchronisation cumulent trois apprentissages dès l'ouverture. | Première manipulation : juxtaposer deux extraits déjà courts ; timeline révélée au deuxième dossier. | Modifier fortement. |
| G1 — Atelier | Le résultat visible permet des essais rapides. | Des modules abstraits évoquent un éditeur technique ; trop de possibilités sans intention claire. | Départ avec objets concrets et deux raccordements possibles ; composants abstraits seulement après réussite. | Modifier. |
| G2 — Intervenants | Chaque déplacement produit un retour immédiat ; le tour par tour tolère les interruptions. | Le duo augmente la charge initiale et l'urgence concurrence l'apprentissage. | Premier lieu paisible et un seul personnage contrôlable ; partenaire introduit par une action coopérative. | Retenir sous condition de nouvelle ouverture. |
| L1 — Atelier de quartier | Le même geste manuel puis délégué explique l'automatisation par contraste vécu. | Tracer précisément devient pénible au doigt ; attente pendant l'exécution. | Raccordement par deux touchers, étapes discrètes, accélération jusqu'au prochain changement utile. | Retenir ; concurrent direct de C1. |
| L2 — Dernier Témoin | Petites salles : attention délimitée et objectifs locaux. | Explorer, comparer et réparer peuvent exiger trois interfaces différentes. | Un même dispositif de sélection et aperçu pour les trois gestes ; urgence scénarisée après familiarisation. | Modifier. |

## Désaccord et préférence

Je refuse une interface réalistement illisible au motif du thriller : texte minuscule, commandes mouvantes ou faux blocages rendraient les erreurs impossibles à attribuer. L'incertitude concerne le monde ; l'interface conserve une grammaire fiable.

Préférence : **C1**, avec la délégation d'un circuit de L1. Sa première action est facile à montrer ; le port fait apparaître les interdépendances sans introduire une ville entière. Cette préférence serait invalidée si des novices ne distinguent pas leur route d'une route déléguée, si les circuits masquent systématiquement les personnages, ou si les manipulations deviennent répétitives après trois livraisons.

## Audit proposé des vingt premières minutes

Il s'agit d'un protocole prévisionnel à adapter au script final. Pour **chaque minute**, consigner : compréhension nécessaire ; nombre de nouveautés ; action remplaçant la lecture ; explication supprimable ; mécanisme reportable ; information montrable dans le monde. Relever les erreurs d'interface séparément des erreurs de stratégie.

| Minute | Hypothèse à examiner / nouveauté maximale |
| --- | --- |
| 1 | Sélectionner le robot puis sa destination / 1 geste. |
| 2 | Comprendre l'arrivée et la satisfaction d'un destinataire / 0. |
| 3 | Refaire avec une destination différente / 0. |
| 4 | Rencontrer un passage occupé / 1 contrainte. |
| 5 | Modifier sa préparation sans conséquence punitive / 1 annulation. |
| 6 | Obtenir une proposition d'automatisation / 1 fonction. |
| 7 | Voir le robot travailler sur le même trajet / 0. |
| 8 | S'occuper d'une seconde demande / 0. |
| 9 | Identifier les limites du circuit délégué / 1 périmètre. |
| 10 | Interruption et reprise : retrouver son intention / 0. |
| 11 | Constater une divergence terrain/rapport / 1 indice. |
| 12 | Examiner la source avec une action / 1 outil. |
| 13 | Comparer deux informations contextualisées / 0. |
| 14 | Choisir quoi vérifier avec une action limitée / 1 coût. |
| 15 | Appliquer une correction locale / 0. |
| 16 | Observer une demande restée sans réponse / 0. |
| 17 | Recevoir une demande d'accès supplémentaire / 0 nouveau menu. |
| 18 | Anticiper précisément l'ordre engagé / 0. |
| 19 | Voir conséquences directe et différée / 0. |
| 20 | Reconstituer la chaîne en manipulant trois événements / 0 jargon requis. |

Le test doit inclure téléphone tactile et clavier, agrandissement du texte, interruption et son coupé. Mesurer première action utile, aides nécessaires et confusions ; demander ensuite une prédiction sur une situation nouvelle. Aucune de ces mesures n'a encore été réalisée.
