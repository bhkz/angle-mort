# Spécialiste 7 — UX / interaction : contribution indépendante

Contribution rédigée avant lecture des propositions. Les recommandations ci-dessous sont des hypothèses de conception, sans résultats de playtest.

## Recherche utile

Le W3C fixe au critère 2.5.8 de WCAG 2.2 un minimum de 24 × 24 pixels CSS pour les cibles, avec exceptions notamment d'espacement. Pour ce jeu tactile, je propose une cible de conception plus confortable de 44–48 pixels CSS pour les commandes principales : ce choix dépasse ce minimum, il n'est pas une garantie d'accessibilité. [W3C, taille des cibles](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

Le critère 2.5.7 demande une alternative au déplacement par glissement lorsqu'il n'est pas essentiel. Un raccordement de réseau doit donc fonctionner aussi par « toucher le départ, toucher l'arrivée ». Cette alternative facilite également une interaction précise sur téléphone. [W3C, mouvements de glissement](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

La divulgation progressive consiste à présenter d'abord les fonctions prioritaires, puis les fonctions secondaires quand elles deviennent utiles. Son risque est de cacher les fonctions que le joueur doit découvrir. Nous devons différer leur introduction narrative, puis conserver un accès stable. [Nielsen Norman Group, Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

## Conclusions indépendantes

La première promesse doit tenir dans une action visible : rétablir un service, livrer un objet, ouvrir un passage. Une présentation institutionnelle retarderait le plaisir. Objectif de prototype : première conséquence manipulée en moins de trente secondes ; ce seuil reste à tester.

Une scène, une action principale, un court besoin humain. Ensuite une deuxième règle, puis la combinaison des deux. La complexité vient des relations entre objets connus. Une nouvelle permission doit répondre à un obstacle rencontré, avec libellé concret : « Modifier les tournées » plutôt que « agentivité niveau 2 ».

Sur mobile portrait : monde en partie supérieure, panneau d'action inférieur stable ; carte zoomable par commandes accessibles. Aucune information indispensable au survol. Le toucher sélectionne et montre un aperçu ; une commande explicite exécute les engagements. Pas de confirmation répétée pour les sélections ordinaires. Annulation disponible pendant la préparation ; conséquences engagées clairement distinguées.

La scène peut mentir à travers un rapport diégétique, mais l'interface doit rester fiable sur ce que le joueur a demandé et exécuté. Les effets inconnus restent inconnus ; l'ordre donné ne doit jamais être ambigu.

Prévoir commandes clavier, focus visible, texte HTML redimensionnable, sous-titres et historique, alertes visuelles doublant le son, motifs doublant la couleur, réduction des mouvements et pause. La tension doit venir de ressources limitées et d'informations incomplètes ; la lecture ne consomme pas automatiquement un chronomètre réel.

Sauvegarder après les décisions et permettre de reprendre avec « situation / dernier ordre / prochaine action ». L'écran de téléphone réduit et les interruptions quotidiennes doivent être inclus dans les essais, dès la maquette.
